# Plan — Enemy AI: Setup (archetype & spawning)

**Group:** `AI` (part 1 of 2 — pairs with [2026-07-03_AI_behaviour.md](2026-07-03_AI_behaviour.md)).
**Graduated from** [archive/2026-06-08_next-features.md](2026-06-08_next-features.md) §C #5.
**Status:** ✅ Shipped 2026-07-03. `monster_grunt` archetype (new `AIState` component, coloured box via the `Colour` albedo path, kinematic Jolt body created in `buildWorld`), registered as a `monster_grunt` classname, 2 spawned in the showcase. New `enemyDeathSystem` (tick after `playerDeathSystem`) removes grunts at 0 health. Shootable/damageable came free via existing `raycastEntities` + `applyDamage`; triggers were **already** generalised off `TagPlayer` to `TagTriggerable`, so the grunt simply omits that tag. New headless scenario `monster_grunt` (blocks player + shot dead) — 12/12 green; conventions clean. Behaviour (chase/attack) is the paired plan.

**Goal:** get an enemy entity that **exists, has health, can be shot, and blocks movement** —
*no behaviour yet*. This is the foundation the behaviour plan builds on; splitting it out keeps
the first landable milestone small.

> Enemy AI is the one item the roadmap never formally slotted (the old Ch 14 "Enemy AI" was
> reassigned to Jolt). Treat this as new ground.

## Scope (this plan)
| # | Task | Reuses |
|---|------|--------|
| 1 | **`monster_grunt` classname factory** | register in the classname dispatch table alongside `item_*` / `weapon_*` ([`classname_factory_items.cpp`](../../src/engine/level/classname_factory_items.cpp) pattern). |
| 2 | **Enemy archetype/components** | `Health` (already takes damage via `applyDamage`), `Position`/`Rotation`, a `MeshRenderer`, and a new `AIState` component (created here, *used* by the behaviour plan). |
| 3 | **Jolt body** | a dynamic or character body so the grunt collides with the level and the player, and can be pushed/knocked back. Decide dynamic-rigid vs `CharacterVirtual` (behaviour movement style depends on this — coordinate with the behaviour plan). |
| 4 | **Takes damage & dies** | confirm hitscan/projectile hits register on the enemy body (`raycastEntities`), health drops, and death removes/ragdolls it. Reuses existing combat damage path. |
| 5 | **Spawn in the showcase** | add one or more `monster_grunt` entries to the showcase descriptor so it's visible/shootable. |
| 6 | **Generalise triggers off `TagPlayer`** | triggers currently fire on `TagTriggerable`/`TagPlayer`; make sure enemies can (later) use doors/pads without being teleported/damaged by player-only volumes. Prereq for behaviour. |

## Explicitly out of scope (→ behaviour plan)
State machine, line-of-sight, seeking/pathing, attacking. A grunt from this plan just stands
there and can be killed.

## Verification
